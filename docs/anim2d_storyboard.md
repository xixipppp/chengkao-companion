## 0. 定位与硬约束

### 0.1 产物定义

对题库中**任意一道题** `q`，程序化生成一条 **30~60 秒**的竖屏（9:16）2D 动画讲解视频：

- 画面 100% 由 `CanvasRenderingContext2D` 代码绘制，不预存任何素材、不加载图片、不加载字体文件；
- 覆盖全库（pol 705 / eng 1200 / math 360，含 choice 与 fill 两种题型）；
- 播放器支持播放/暂停、**拖动 seek**、0.5×/1×/1.5×/2× 倍速、重播，并**导出真实 MP4**。

### 0.2 四条硬红线

| # | 红线 | 落地手段 |
|---|---|---|
| R1 | **严禁编造题目内容或答案** | 屏幕上每个字符必须来自 §9.1「文案来源白名单」，渲染器提供 `assertSource()` 开关（开发期开启，命中非白名单字符直接 `console.error` 并跳过该句） |
| R2 | **总时长 30~60 秒** | §6 时长预算 + `fitTimeline()` 全局归一化，返回前 `assert(30 ≤ T ≤ 60)` |
| R3 | **必须程序化生成** | 分镜不得依赖任何人工逐题标注；所有分支判定只能读 `q` 的现有字段（§4/§5 判定表） |
| R4 | **不依赖外部资源** | 无图片、无 webfont、无音频文件（音效走 WebAudio 程序合成，§10.3） |

### 0.3 与视觉规范的坐标系对齐

- 设计稿 **1080 × 1920**，业务代码只写设计稿坐标（`ctx.setTransform(s,0,0,s,0,0)`）【视觉 §0.1】；
- 纵向五区：A 顶栏 `0–160` / B 标题 `160–420` / **C 舞台 `420–1450`（必须 `clip()`）** / D 字幕 `1450–1720` / E 控制 `1720–1920`【视觉 §1.2】；
- 舞台内三段：C1 题干位 `440–700`、C2 主体位 `720–1240`、C3 解析位 `1260–1430`【视觉 §1.2】；
- 同屏可见汉字总量 **≤ 90 字**，超出即拆成两个场景【视觉 §7.3】——这条直接约束了 §6 的「切屏」逻辑。

## 1. 时间轴模型（核心工程约束）

### 1.1 纯函数原则

> **`frame(t) → 画面` 必须是纯函数**：给定全局时间 `t`（秒），画面完全确定，不依赖「上一帧状态」。

理由：本播放器需要 **拖动 seek / 暂停 / 倍速 / 重播**。只要画面是 `t` 的纯函数，这四个能力天然正确，不需要任何状态回滚逻辑。

具体实现：

```js
// ① 渲染主入口：只接受 t
function renderAt(t){                 // t ∈ [0, T]
  const sc = sceneAt(TL, t);          // 二分查找当前场景
  drawChrome(t);                      // 固定层：角标/字幕/进度/水印
  drawScene(sc, t - sc.t0);           // 场景内局部时间
  drawSubs(t);
}
// ② 粒子/随机：必须 seeded，禁止 Math.random()
const rnd = mulberry32(hashStr(q.id));   // 同一题每次渲染粒子轨迹完全一致
// ③ 倍速：只改 t 的推进速率，不改 T
let t = 0; function tick(dt){ t = Math.min(T, t + dt * rate); }
// ④ seek：直接赋值重绘
function seek(sec){ t = clamp(sec, 0, T); renderAt(t); }
```

**禁止**：帧计数驱动、累积位移（`x += v`）、`Math.random()`、场景间共享可变状态。
**允许**：离屏缓存背景/静态网格、`measureText` 结果缓存（纯缓存，不影响画面）。

### 1.2 时间轴数据结构（TL）

`buildTimeline(q)` 返回：

```js
{
  qid: q.id, subj: q.subj, t: q.t, m: q.m,
  total: 42.6,                       // 秒，已过 fitTimeline() 归一化
  fps: 30,                           // 导出帧率
  theme: 'pol'|'eng'|'math',         // 【视觉 §2.1】
  dig: 'concept'|'timeline'|'news'|'phoneme'|'colloc'|'cloze'|'reading'|'conv'
      |'limit'|'curve'|'area'|'partial'|'prob'|'plain',   // 差异化分镜 ID，见 §4.4
  scenes: [                          // 严格按 t0 升序、首尾相接、不重叠
    { id:'S01', type:'intro',  t0:0.0,  dur:2.4, in:'fadeUp', out:'wipeIn',
      sub:[{t0:0.30, t1:2.30, text:'...', hi:false}],
      layers:{ /* 本场景专用数据，见各场景定义 */ } }
  ],
  subs: [ {t0, t1, text, hi} ],      // 展开后的字幕轨（供 D 区渲染）
  chapters:[ {t0:0, label:'片头'}, {t0:2.4, label:'题干'}, ... ]  // 进度条打点
}
```

**场景首尾相接、不重叠**：`scenes[i+1].t0 = scenes[i].t0 + scenes[i].dur`，`T = Σ dur`。
场景切换的 `wipeIn`（320ms）在**下一个场景的 dur 内部**播放，不额外占用时间【视觉 §5.2-10】。

### 1.3 场景类型枚举

`intro | stem | opts | elim | reveal | steps | given | target | derive | answer | tip | recap`

其中 `given/target/derive/answer` 为 fill 专属（§5），`recap` 为时长补足专用（§6.4）。

### 2.2 HOOK：前三秒钩子（强制）

短视频前三秒决定完播率。默认模式 `HOOK_MODE = 'answer-flash'`：

| 时刻 | 画面 | 说明 |
|---|---|---|
| 0.00–0.30 | 黑场 → 背景渐变淡入 | — |
| 0.30–1.60 | 片头题卡正常播放（科目胶囊 `badgePop`、主标题 `fadeUp`） | 【视觉 §4.4】 |
| **1.60–2.20** | **答案文本 H0 96px 金色 + 12px 黑描边，从画面中心 `scale 1.6→1.0` + `alpha 0→1` 砸下，叠 `flash` 白闪 12%** | 字幕同步 `{答案文本}`，`hi:true` |
| 2.20–2.40 | 答案淡出，`wipeIn` 转场进入 S02 | — |

- 备选 `HOOK_MODE = 'module-flash'`（不提前泄题）：把 1.60–2.20 的画面换成 `{模块名}` + 「`30` 秒拿下」大字（`30` 为模板数字，非题目数据）。
- **HOOK 只能展示字段原文**（答案来自 `q.o[q.a]` / `q.ans[0]`），禁止任何改写或概括。
- 若 `q.a` 越界或 `q.o` 缺失 → HOOK 自动降级为 `module-flash`（§9）。

### 2.3 记忆句抽取规则（`memoryLine(q)`，禁止生成式改写）

按优先级取**第一条命中者**，全为字段原文：

1. `splitSol(q.sol)` 中命中 `/故选|因此|所以|关键是|注意|记住|核心|本质|标志|根本|区别/` 的**最后一句**；
2. `splitSol(q.sol)` 的**最后一句**（兜底，仍为空则下一级）；
3. `q.hint`（题库 **100%** 有此字段）；
4. `modById(q.m).ds`（模块套路描述，如 m4 = 「只要记住：求谁的偏导，就把其他字母当常数。」）；
5. 都没有 → **S07 场景整体省略**，只剩答案大字。

> 实测：全库 `hint` 覆盖率 100%、`sol` 覆盖率 100%，因此 3 级以下几乎不会触发；但规则必须写死以防题库后续增量。

## 4. 三科差异化分镜（重点）

### 4.0 总原则

三科**共用** S01 / S02 骨架与 S07 / S08 收尾；**差异化只发生在「主体位 C2」**——即 `S03/S04/S05`（choice）或 `S03F/S04F/S05F`（fill）与 `S06` 的画面形态。

差异化 ID（写入 `TL.dig`）由 **§4.4 判定表** 唯一确定，渲染器按 `dig` 分发到对应的 `drawStage_xxx(t)`。

### 4.1 政治 `pol`（主色 `#ff7a9c`）

**视觉母题**：概念关系图 / 关键词气泡 / 排除法 / 时政条目。
**通用元素**：右下角常驻「套路条」= `modById(q.m).ds`（字段原文，44px 次文字，底 `rgba(28,20,48,.72)`）。

#### 4.3.7 ★ 曲线解析白名单（防编造的关键闸门）

```js
// tryParseCurve(q) → {ok:true, f:(x)=>y, kind:'poly'|'circle'|'elem'} | {ok:false}
// 仅在「题干中的函数表达式能被白名单原子完全解释」时才 ok:true
const ATOM = [
  /^x$/, /^x\^?[23]$/, /^x[²³]$/,                    // x, x^2, x^3
  /^(sin|cos|tan|ln|lg)\(?x\)?$/,                     // 初等函数
  /^e\^?x$/, /^√?\(?x\)?$/, /^1\/x$/,                 // e^x, √x, 1/x
  /^[+-]?\d*\.?\d*$/,                                 // 常数项
];
// 流程：
// 1. /y\s*=\s*([^,，;；。]+)/ 取右侧 expr（取不到 → ok:false）
// 2. expr 按 [+-] 切项（保留符号），每一项必须匹配上表某个 ATOM，或形如 k·atom（k 为数字系数）
// 3. 任一项不匹配 → ok:false → 走「抽象示意曲线 + 示意图角标」
// 4. 隐式二次：/x[²2]\s*\+\s*y[²2]/ → kind:'circle'，从 (x-a)²+(y-b)²=r² 抽 a,b,r
```

**`ok:false` 时的强制行为**：画一条固定的平滑 Catmull-Rom 示意曲线（控制点为固定常量，与题目无关），并在画面右上角画一个【固定】`示意图` 灰色角标（26px）。**此时画面上不得出现任何刻度数值、函数值或坐标点**。

> 实测：math 360 题中能安全解析的比例不高（题干多为 `lim(x→0) x/cosx`、`d/dx ∫₀ˣ …`），因此「示意曲线 + 公式逐行」会是 math 的主力形态——这是**刻意的设计**：宁可抽象，不可编造。

## 5. 填空题专属分镜（`q.t === 'fill'`）

### 5.1 与 choice 的结构对照

| choice | fill | 说明 |
|---|---|---|
| S03 选项飞入 | **S03F 已知条件拆解** | 没有 ABCD，用题干自身的结构代偿 |
| S04 错误项排除 | **S04F 求解目标** | 没有可排除项，改用「明确求什么」建立期待 |
| S05 正确项揭晓 | **S06F 答案揭晓**（后移） | fill 的答案必须先推导后揭晓，否则无说服力 |
| S06 解析推演 | **S05F 推导推演**（前移） | 顺序与 choice 相反：choice 先给结论，fill 先走过程 |

> **为什么 fill 要「先推导后揭晓」**：选择题观众可以接受「先亮答案再讲为什么」（有 ABCD 做锚点）；填空题没有锚点，先亮答案会让后面的推导失去张力。这是三科 144 道填空题统一适用的节奏。

### 5.2 `S03F` 条件行切分算法（`splitGiven(q.q)`）

```js
function splitGiven(q){
  // ① 按分隔符先切
  let parts = String(q).split(/[，,；;]/).map(s=>s.trim()).filter(Boolean);
  // ② 引导词识别：以这些词开头的 part 独立成「条件行」
  const LEAD = /^(设|已知|若|其中|当|令|由|求|函数|曲线|方程)/;
  const conds = parts.filter(p => LEAD.test(p) || /[=≈<>∈∫∂]/.test(p) || /_/.test(p));
  // ③ 合并过短行（C<4）到前一行
  // ④ 上限 4 行；超出则保留前 3 行 + 把剩余合并为第 4 行（只合并，不删字）
  // ⑤ 全部为空 → 返回 [q]（整题一行）
  return conds.length ? conds.slice(0,4) : [String(q)];
}
```

- 行渲染：C1 位，40px/400，行高 64，`fadeUp` `stagger 90ms`；
- 含 `______` 的行：空位渲染为**主色虚线占位块**（宽 160，高 56，圆角 8，底色主色 8%），`highlightSweep` 扫过一次；

## 6. 时长预算规则

### 6.1 字数统计函数 `C(s)`

中英混排、公式混排下，用「视觉字数」而非字符数：

```js
function C(s){
  const ch = Array.from(String(s || ''));
  let n = 0;
  for(const ch2 of ch){
    if(/[\u4e00-\u9fa5\u3000-\u303f\uff00-\uffef]/.test(ch2)) n += 1;      // CJK/全角 = 1
    else if(/\s/.test(ch2)) continue;                                       // 空白不计
    else n += 0.5;                                                          // ASCII/数字/符号 = 0.5
  }
  return n;
}
```

> 实测校准：eng 题干 100 字符 → `C ≈ 50`；math `∫₋₁¹ (xcos²x + 2) dx` → `C ≈ 9`。

### 6.2 各场景时长公式

**统一形式**：`dur = max(A_in, 0) + Σ dwell(screen) + gap`，其中

- `A_in` = 该场景入场动画总时长（取自【视觉 §5.2】动效表，含 `stagger`）；
- `dwell(screen) = clamp(C(screen) / READ_RATE, MIN_DWELL, MAX_DWELL)`，即**字幕停留时间由该屏字数决定**；
- `gap = 0.15`（场景间呼吸）；
- 每个场景再套一层 `[min, max]` 硬 clamp。

**常量表**（已用全库 2265 题跑批校准，见 §6.6）：

```js
const DUR = {
  READ_RATE : 5.5,   // 视觉字/秒（学习类讲解的舒适区；跑批后选定，勿低于 5.0）
  MIN_DWELL : 1.2,   // 单屏最短停留（低于此值读不完 14 字×2 行）
  MAX_DWELL : 4.8,   // 单屏最长停留
  GAP       : 0.15,  // 场景间呼吸
  INTRO     : 2.4,   // S01 固定【视觉 §4.4】
  OUTRO     : 3.0,   // S08 固定【视觉 §4.5】
  T_MIN     : 30, T_MAX   : 60,
  T_SOFT_MAX: 56, T_SOFT_MIN: 31,   // 归一化软目标（留 1s 安全边）
  MAX_STEPS : 8,     // S06/S05F 最多步数
  RECAP_MAX : 6.0,   // S09 单次最多补 6s（超过宁可拉伸，不让回看卡喧宾夺主）
  STRETCH_MAX: 1.6,  // 补足时最大拉伸倍率
  SHOW_HINT : true,  // S03B 思路提示场景开关
};
```

| 编号 | 场景 | 公式 | clamp |
|---|---|---|---|
| `F01` | S01 片头 | `2.4`（固定，含 HOOK 0.6s） | — |
| `F02` | S02 题干 | `max(0.42 + 0.09*(L-1), Σ dwell) + GAP`；`L` = 行数（pol 20/行、eng 26/行、math 22/行）；`Σ dwell` 按切屏后每屏算 | `[3.2, 9.0]` |
| `F03` | S03 选项飞入 | `A_in = 0.48 + 0.11*(n-1)`；`dwell = clamp(Cmax/READ, 1.2, 3.6)`；`dur = A_in + dwell + GAP` | `[2.6, 6.5]` |
| `F03B` | S03B 思路提示 | `dur = 0.42 + clamp(C(hint)/READ, 1.5, 4.0) + GAP` | `[1.8, 4.4]` |
| `F03F` | S03F 已知条件 | `A_in = 0.42 + 0.09*(L-1)`；`dwell = clamp(ΣC(行)/READ, 1.2, 3.0)`；`+GAP` | `[2.0, 4.2]` |
| `F04` | S04 排除 | `A_in = 0.46 + 0.22*(n-2)`；`dur = A_in + 0.5 + GAP` | `[1.2, 2.6]` |

| `F08` | S08 结尾 | `3.0`（固定） | — |
| `F09` | S09 回看补足 | `补足值`（§6.4） | `[2.0, 6.0]` |

### 6.3 切屏：字幕屏数反过来决定时长

**这是本规范的耦合点**——场景时长不是先定的，而是由「这段话要切成几屏字幕」反推：

```js
function screensOf(text, maxC = 14, maxLines = 2){   // 【视觉 §3.3-6】单行 ≤14 字、≤2 行
  const shots = [];                                   // 每屏 ≤ 28 视觉字
  // 1) 按 [。！？；;] 断句
  // 2) 句内按 [，、,：] 断 clause
  // 3) 贪心装行：累计 C > 14 → 换行；行满 2 行 → 结束本屏、开新屏
  // 4) 单个 clause 自身 C > 14 → 中文按字切；英文按空格整词下移（不拆词）
  // 5) 每屏最短 dwell = MIN_DWELL = 1.2s
  return shots;                                       // [{lines:[...], C:n}]
}
```

参考实现（已跑批验证，可直接落地）：

```js
function screensOf(text, cap = 28){          // cap = 2 行 × 14 字
  const clauses = String(text||'').split(/(?<=[。！？；;，、,：:])/).filter(Boolean);
  const out = []; let cur = '';
  const chop = c => {                        // 超长 clause 按 C 切成 ≤28 的块
    const ps = []; let acc = 0, buf = '';
    for (const ch of Array.from(c)) { const w = chW(ch);
      if (acc + w > cap) { ps.push(buf); buf = ''; acc = 0; }
      buf += ch; acc += w; }
    if (buf) ps.push(buf); return ps;
  };
  for (const c of clauses) for (const p of (C(c) > cap ? chop(c) : [c])) {
    if (cur && C(cur) + C(p) > cap) { out.push(C(cur)); cur = p; } else cur += p;
    if (C(cur) >= cap) { out.push(C(cur)); cur = ''; }
  }
  if (cur) out.push(C(cur));
  return out.length ? out : [0];
}
```

`Σ dwell = Σ clamp(screen.C / READ_RATE, MIN_DWELL, MAX_DWELL)`。
**同屏汉字 ≤ 90**【视觉 §7.3】约束：若题干 + 选项同屏超过 90 字，S03 强制把 S02 的题干缩为「首屏 28 字 + `…`」后再飞入选项（`…` 是省略标记，非内容编造）。

### 6.4 全局归一化 `fitTimeline()`

```js
function fitTimeline(scenes){
  const FIXED = new Set(['S01','S08']);                          // 不可压缩、不可拉伸
  const FLEX  = new Set(['S02','S03','S03B','S03F','S05F','S06','S06F','S07']);
  let T = sum(scenes.map(s => s.dur));

  // ── A. 超限：先压缩，再砍步，最后硬缩放 ────────────────────────
  if (T > DUR.T_SOFT_MAX) {
    const k = DUR.T_SOFT_MAX / T;
    scenes.forEach(s => { if (FLEX.has(s.id)) s.dur = Math.max(s.dur * k, s.min * 0.85); });
    T = sum();
    while (T > DUR.T_SOFT_MAX && stepCount(scenes) > 2) { dropLastStep(scenes); T = sum(); }
    if (T > DUR.T_MAX) { const k2 = DUR.T_MAX / T; scenes.forEach(s => { if (!FIXED.has(s.id)) s.dur *= k2; }); T = sum(); }
  }

  // ── B. 不足：先补 S09（真内容），再轻度拉伸 ────────────────────
  //    ※ 顺序很重要：先补内容再拉伸，避免把整片拖慢 1.5× 的「注水感」
  let recap = 0;
  if (T < DUR.T_SOFT_MIN) {
    recap = clamp(DUR.T_SOFT_MIN - T, 2.0, DUR.RECAP_MAX);
    T += recap;
    if (T < DUR.T_SOFT_MIN) {                                   // 仍不足 → 拉伸（≤1.6×）
      const k = Math.min(DUR.T_SOFT_MIN / (T - recap), DUR.STRETCH_MAX);
      scenes.forEach(s => { if (FLEX.has(s.id)) s.dur = Math.min(s.dur * k, s.max * 1.5); });
      T = sum() + recap;
    }
    if (recap > 0) scenes.splice(indexOf('S08'), 0, makeRecap(recap));  // 插在结尾卡之前
    if (T < DUR.T_MIN) T = DUR.T_MIN + 0.5;                     // 最终兜底
  }

  // ── C. 落位 & 断言 ────────────────────────────────────────────
  let acc = 0; scenes.forEach(s => { s.t0 = acc; acc += s.dur; });
  console.assert(acc >= DUR.T_MIN && acc <= DUR.T_MAX, 'anim2d: 时长越界 ' + acc);
  return { scenes, total: acc };
}
```

- `S09`（回看补足）永远插在 **S08 之前**，不破坏「结尾卡是最后一屏」的收尾节奏；
- **补时优先级：真内容 > 拉伸**。`RECAP_MAX = 6.0` 是刻意的——回看卡最多补 6 秒，剩下的一律靠轻度拉伸（≤1.6×）解决，避免回看卡喧宾夺主；
- 步骤数上限 `MAX_STEPS = 8`：超出时**优先合并相邻短句**（`C<8` 的句并入下一句，用 `；` 连接原句——注意这是连接原文不是改写），仍超 8 则保留**前 7 句 + 最后一句**（结论句必须留）；
- `S03B` 在 `D2/D3/D7` 降级下**不能被移除**（`hint` 是 100% 覆盖字段，是这些场景唯一的合法内容来源），因此它同时属于 `FLEX` 与「降级保留集」。

### 6.5 长文本规则（eng e3/e4 专供）

实测：eng 题干 p90 = 100 字符、p99 = 295、max = 346；sol p99 = 191、max = 626。

| `C(q.q)` | 处理 |
|---|---|
| ≤ 28 | 单屏，正常 |
| 28 ~ 84 | 正常切屏（≤3 屏），S02 最多 3 屏 |

|---|---|

### 7.4 ★ 重点突出（`hi:true`）判定

1. **答案文本**：`ansText(q)` 本身（`q.o[q.a]` 或 `q.ans[0]`）——**永远 hi**；
2. 含结论词：`/故选|因此|所以|故|答案|正确的|正确的是/`；
3. 含强调词：`/注意|关键|核心|本质|标志|根本|唯一|区别|记住|陷阱/`；
4. 含否定排除：`/不是|错误|排除|不属于|不符合/`（S04 场景内）；
5. 命中 §4.1.1 的**核心词**子串（仅 `concept` 形态）；
6. 命中 §4.2.2 的**语法术语**（如「虚拟语气」）——子串 hi，非整句。

### 7.5 数学排版 `parseMathRuns(s)`

题库数学文本是 **Unicode 混排**（既有 `x²`、`∫₋₁¹`、`∂²z/∂x∂y`，也有 `e^(−x)`、`x→0`），**不需要 TeX 解析器**，只需转成「富文本 run」：

```js
function parseMathRuns(s){
  // 返回 [{txt, sup:false, sub:false, size:1, dy:0}]
  // ① Unicode 上标 ⁺⁻⁰¹²³⁴⁵⁶⁷⁸⁹ⁿ → {sup:true, size:.62, dy:-.36em}
  // ② Unicode 下标 ₀₁₂₃₄₅₆₇₈₉ → {sub:true, size:.62, dy:+.22em}
  // ③ ^ 后紧跟 (...) 或单字符 → sup（吞掉 ^ 与括号）
  // ④ _ 后紧跟 (...) 或单字符 → sub
  // ⑤ 其余（含 lim ∫ ∂ √ → × ÷ ± ≤ ≥ 等符号）→ 普通 run，字号不变
}
```

- 渲染：逐 run 绘制并累加 `measureText().width`，基线按 `dy` 偏移；**不支持时整体按普通文本绘制**（降级不影响正确性，只是不美观）。

### 10.2 导出真实 MP4（离线渲染）

**不要使用 `canvas.captureStream()` + `MediaRecorder` 实时录制**——会掉帧、时长不可控、且 Safari 只出 MP4/H.264 但码率不可控。

推荐：**离线逐帧渲染 + WebCodecs 编码**。

```js
async function exportMp4(TL, {w=1080, h=1920, fps=30} = {}){
  const N = Math.round(TL.total * fps);
  // ① 主路径：WebCodecs（Chrome 94+ / Edge / Safari 16.4+）
  if (window.VideoEncoder) {
    const enc = new VideoEncoder({output: onChunk, error: e => reject(e)});
    enc.configure({codec:'avc1.640028', width:w, height:h, bitrate: 6_000_000, framerate: fps});
    const muxer = new Mp4Muxer({target: new ArrayBufferTarget()});   // vendor/mp4-muxer.js
    for (let i = 0; i < N; i++) {
      renderAt(i / fps);                       // 纯函数，任意顺序渲染都正确
      enc.encode(new VideoFrame(canvas, {timestamp: Math.round(i * 1e6 / fps)}));
      if (i % 10 === 0) await yieldToUI(i / N);   // 让出主线程，更新进度条
    }
    await enc.flush(); muxer.finalize();
    return new Blob([muxer.target.buffer], {type:'video/mp4'});
  }
  // ② 兜底：MediaRecorder → video/webm;codecs=vp9
  //    ※ 导出前必须提示用户「当前浏览器不支持 MP4 直出，已导出 WebM（可用格式工厂转换）」
  //    ※ 禁止把 webm 直接改名 .mp4
}
```

- 离线渲染的好处：导出时长**严格等于** `TL.total`，不掉帧，可按帧 seek 渲染（并行友好）；
- 导出分辨率默认 **1080×1920 @ DPR=1**，提供「高清 1440×2560」选项（渲染时间约 1.8×）；
- `sw.js` 需要把 `vendor/mp4-muxer.js` 排除在 precache 之外（按需加载，同 `assets/kaodian/` 策略）。

### 10.3 音效（程序化，无音频文件）

用 `AudioContext` 合成，不引入任何音频资源：

| 事件 | 合成 |
|---|---|
| `cardFlyIn` 每张 | 短 tick：600Hz 方波，40ms，`gain 0.06`，`exponentialRamp` 淡出 |
| `wrongShake` | 低频：180Hz 锯齿，90ms，`gain 0.05` |
| `correctPulse` | 琶音 C5→E5→G5（523/659/784Hz），各 90ms 间隔 |

| 背景 pad | 可选：主音 + 五度，三角波，`gain 0.015`，全程循环（默认**关闭**，避免干扰） |

导出 MP4 时音频轨通过 `AudioEncoder`（AAC）与视频一起 mux；无 `AudioEncoder` 时**导出无声视频**（不报错）。

### 13.2 🔴 必修：406 题成片时长 = 29.999999999999996，违反「≥30s」硬规范

**现象**：跑批 `Anim2D.build()` 全库 2265 题，**406 题** `spec.total < 30`（实测值 `29.999999999999996`，`T - 30 = -3.55e-15`），其中 pol 259 / eng 90 / math 57。

**根因**：归一化时 `k = MIN / raw` 后逐场景 `s.dur *= k` 再累加，浮点乘法累积误差导致总和略小于 30。全部 406 题都是 `raw < 30` 被拉伸的情形，`raw ≥ 30` 的题无一越界——可以确认是纯浮点漂移，不是公式问题。

**修复**（`data/anim2d.js` 归一化处，两行即可）：

```js
if(Math.abs(k - 1) > 1e-6){
  t = 0;
  sc.forEach(function(s){ s.dur *= k; s.t0 = t; s.t1 = t + s.dur; t += s.dur; });
  if(raw < MIN) t = MIN; else if(raw > MAX) t = MAX;   // ← 新增：消除浮点漂移
  caps.length = 0;
  sc.forEach(function(s){ addCaps(s.t0, s.dur, s.caps); });
}
spec.total = Math.round(t * 1000) / 1000;               // ← 新增：统一保留 3 位小数
```

### 13.3 🟡 建议：81% 的题靠整体拉伸凑时长，中位成片恰好 30.0s

**现象**：现有实现 `raw` 的 p50 = **26.9s**、p90 = 32.0s、max = 42.1s；`raw < 30` 的题占 **81%**，被统一 `k = 30/raw` 拉伸（最短的 `mat18_f16` 拉伸了 **1.535×**）。结果是**半数成片恰好 30.0s**，且短题整体节奏被拖慢。

**建议**（已在 §6 规范中定义，`tools/anim2d_dur_check.js` 已验证）：

1. **补 S03B「思路提示」场景**（`q.hint` 原文，全库 100% 覆盖）——把 `raw` 中位从 26.9s 提到 **32.1s**，需要拉伸的题从 81% 降到 **39%**；
2. **补时优先级改为「先补真内容、再拉伸」**：先插 S09 回看卡（≤6s），仍不足才拉伸（≤1.6×）；
3. 把 `total` 目标从 30 提到 `T_SOFT_MIN = 31`，留 1s 安全边。

### 13.4 🟡 建议：三科差异化与降级规则尚未在实现中体现
